## Stack Snapshot

- React 19 + TypeScript, bundled with Vite (`frontend/vite.config.ts`).
- TanStack Query orchestrates API reads/mutations and cache invalidation.
- TanStack Router owns the `/auth/*` and `/app/*` route shells, keeping login, unlock, and workspace state in sync with the URL.
- Zustand stores keep decrypted note state in memory only.
- shadcn/ui components provide accessible primitives with Tailwind styling.
- Auth + crypto live entirely inside the browser; the API never sees plaintext note content.

## Data Fetching Strategy

- `QueryClientProvider` wraps the app and enforces consistent retry/staleness behaviour.
- `useNotes` and `useAnnouncements` expose the same API as before, but internally call `useQuery` / `useMutation` so cache updates stay centralized.
- Mutations (`restoreNote`, `deleteNote`, share-link actions) update in-memory state via `queryClient.setQueryData`, keeping decrypted note content inside the browser only.
- Admin dashboards render user tables with TanStack Table, wiring server-side sorting into the shared query cache.

## State Stores

- `stores/authStore.ts`: tracks JWT token state, current user metadata, and theme preference persisted in `localStorage`.
- `stores/collaborationStore.ts`: manages active collaborators per note, dispatched by WebSocket events.
- `stores/shareLinksStore.ts`: caches share-link metadata to avoid redundant API calls when toggling visibility.
- `stores/templatesStore.ts` (within templates feature): keeps decrypted templates after first load.

All stores enforce **decrypted data stays in memory**; only identifiers or encrypted payloads persist to storage.

## API Access Patterns

- Each feature module depends on the domain services exported from `services/api` (e.g., `authService`, `contentService`, `socialService`). They all return typed responses validated by shared Zod schemas under `lib/schemas`.
- On 401 responses, the shared `ApiClient` clears keys, tokens, and salts, then redirects to `/login`.
- File uploads stream through `attachmentService.ts`, which includes the decrypted note ID and uses `FormData` to avoid JSON encoding large payloads.

## Testing Strategy

- Component tests (`*.test.tsx`) render against mocked Zustand stores for deterministic behavior.
- `CryptoService.test.js` uses the real libsodium WASM bundle to guarantee encryption compatibility.
- `e2e.test.tsx` exercises the full login + note flow with MSW mocks for backend endpoints.

<Aside type="tip">
When adding new UI flows, keep API shims inside `services/*` so mocks remain centralized.
</Aside>
