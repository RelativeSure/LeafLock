## Modern Authentication Package

LeafLock uses a modular Go authentication package with JWT tokens, Argon2id password hashing, and TOTP MFA.

**Architecture** (`backend/auth/`):
- `models.go` - Type-safe models, structured error codes
- `session.go` - Redis-backed encrypted session management
- `password.go` - Argon2id hashing (64MB memory, 3 iterations), password reset
- `mfa.go` - TOTP + 10 backup codes implementation
- `service.go` - Coordinating service layer
- `handlers.go` - HTTP API (13 endpoints)
- `middleware.go` - JWT validation, auth guards

**Key Features**:
- Password strength validation (12+ chars, mixed case, digits, special)
- Account locking (5 failed attempts = 15min lockout)
- XChaCha20-Poly1305 encrypted sessions
- 24-hour session duration
- 5-minute MFA session window

## Multi-Factor Authentication (MFA)

RFC 6238 TOTP implementation with encrypted secret storage.

### Configuration

**TOTP Settings**:
- Algorithm: SHA-1 (RFC standard)
- Time step: 30 seconds
- Code length: 6 digits
- Secret storage: XChaCha20-Poly1305 encrypted in `mfa_secret_encrypted`
- Implementation: `backend/auth/mfa.go`

**Backup Codes**:
- Count: 10 codes per user
- Format: 12 characters (XXXX-XXXX-XXXX)
- Storage: Argon2id hashed (deterministic salt)
- One-time use, tracked in `mfa_backup_codes_used[]`
- Constant-time comparison for security

**Rate Limits** (`backend/middleware/rate_limit.go`):
- Login: 10 attempts per 5 minutes
- MFA verification: 10 attempts per 5 minutes
- MFA setup/enable/disable: 10 attempts per 5 minutes
- Password reset: 10 attempts per 5 minutes

### Error Codes

**Structured errors** (`backend/auth/models.go`):
- `INVALID_CREDENTIALS` - Invalid email/password
- `ACCOUNT_LOCKED` - Too many failed attempts
- `MFA_REQUIRED` - MFA verification needed
- `INVALID_MFA_CODE` - Wrong TOTP/backup code
- `INVALID_TOKEN` - Invalid JWT or session token
- `EXPIRED_TOKEN` - Token expired
- `USER_NOT_FOUND` - User doesn't exist
- `EMAIL_EXISTS` - Email already registered
- `VALIDATION_FAILED` - Input validation error
- `REGISTRATION_DISABLED` - Registration not allowed

### User Flow

**Setup**: Settings → Security → Enable MFA → Scan QR → Verify Code → Save Backup Codes
**Login**: Email/Password → MFA Prompt → Enter TOTP or Backup Code → Authenticated
**Disable**: Settings → Security → Disable MFA → Enter TOTP/Backup Code → Disabled

### Troubleshooting

**"Invalid MFA code"**:
- Verify device time is synchronized (TOTP requires accurate time)
- Wait for next 30-second window
- Check correct account in authenticator app
- Rate limit: wait 5 minutes after 10 failed attempts
- Implementation: `backend/auth/mfa.go:65` (VerifyTOTP)

**Lost authenticator device**:
- Use saved backup code to login
- Go to Settings → Security → Regenerate Backup Codes
- Or request admin to reset MFA via SQL

**Backup codes exhausted**:
- Login with TOTP from authenticator app
- Navigate to Settings → Security → Regenerate Backup Codes
- Requires password confirmation
- Implementation: `backend/auth/mfa.go:153` (RegenerateBackupCodes)

**Account locked**:
- Lockout duration: 15 minutes
- Trigger: 5 failed login attempts
- Reset: Wait 15 minutes or contact admin
- Implementation: `backend/auth/service.go:312` (incrementFailedAttempts)

**Redis session check**:
<Code code={`# Check if session exists
redis-cli GET "session:<token_hash>"

# Delete session (force logout)
redis-cli DEL "session:<token_hash>"

# Check MFA session
redis-cli GET "mfa_session:<token_hash>"`} language="bash" />

### Database Schema

**Users table MFA columns** (`backend/database/schema.go:22-25`):
- `mfa_enabled` (BOOLEAN) - MFA active flag
- `mfa_secret_encrypted` (BYTEA) - XChaCha20-Poly1305 encrypted TOTP secret
- `mfa_backup_codes` (BYTEA[]) - Argon2id hashed backup codes (10 total)
- `mfa_backup_codes_used` (BYTEA[]) - Hashes of used codes
- `failed_attempts` (INT) - Login failure counter
- `locked_until` (TIMESTAMPTZ) - Account lockout expiry

**Password reset tokens table**:
- `token_hash` (BYTEA) - SHA-256 of reset token
- `expires_at` (TIMESTAMPTZ) - 1-hour expiration
- `used` (BOOLEAN) - Prevents reuse

## Security Notes

- MFA secrets encrypted at rest with `SERVER_ENCRYPTION_KEY`
- Backup codes hashed with Argon2id (deterministic salt for verification)
- Sessions encrypted in Redis with XChaCha20-Poly1305
- Constant-time comparison for TOTP/backup codes (prevents timing attacks)
- All sessions invalidated on password reset
- Password reset tokens: SHA-256 hashed, 1-hour expiration
- Account auto-locks after 5 failed attempts (15-minute lockout)
