Complete API reference for LeafLock authentication endpoints. Supports both **Clerk authentication** (recommended) and **legacy JWT authentication** during migration.

## Authentication Methods

LeafLock supports dual authentication during migration:

1. **Clerk Authentication** (Recommended) - Modern, secure authentication
2. **Legacy JWT Authentication** - For existing users during transition

## Error Codes

All errors include structured `code` field for client-side handling:

| Code | HTTP Status | Description | Handling |
|------|-------------|-------------|----------|
| `INVALID_CREDENTIALS` | 401 | Wrong email/password | Show error, allow retry |
| `ACCOUNT_LOCKED` | 403 | 5+ failed attempts | Show 15min lockout message |
| `INVALID_TOKEN` | 401 | Invalid/missing token | Redirect to login |
| `SESSION_INVALID` | 401 | Session validation failed | Redirect to login |
| `SESSION_EXPIRED` | 401 | Session expired | Redirect to login |
| `USER_NOT_FOUND` | 404 | User doesn't exist | Generic error (security) |
| `EMAIL_EXISTS` | 409 | Duplicate registration | Show "email taken" |
| `VALIDATION_FAILED` | 400 | Input validation error | Show field-specific errors |
| `REGISTRATION_DISABLED` | 403 | Registration not allowed | Show "registration closed" |
| `SESSION_REVOKE_ERROR` | 500 | Session revocation failed | Show generic error |
| `ORGANIZATION_ERROR` | 500 | Organization operation failed | Show generic error |

## Rate Limiting

Redis-based distributed rate limiting using fixed window algorithm:

| Endpoint Group | Limit | Window | Key Format |
|----------------|-------|--------|------------|
| Login | 10 requests | 5 minutes | `limiter:{ip}:/api/v1/auth/login` |
| Registration | 10 requests | 5 minutes | `limiter:{ip}:/api/v1/auth/register` |
| Clerk Session Management | 30 requests | 5 minutes | `limiter:{user_id}:/api/v1/clerk/*` |
| Organization Management | 30 requests | 5 minutes | `limiter:{user_id}:/api/v1/clerk/organizations/*` |

**Rate Limit Response (429)**:
```json
{
  "error": "Too many requests, please try again later"
}
```

**Implementation**: `backend/middleware/rate_limit.go`
**IP Detection**: `backend/utils/network.go` (supports X-Forwarded-For, CF-Connecting-IP)

## Security Notes

**Clerk Authentication**:
- Session tokens validated using Clerk SDK
- Zero-knowledge architecture preserved
- Server never sees plaintext user data
- Automatic token refresh handled by Clerk

**Legacy JWT Authentication**:
- 24-hour token expiration
- Redis-backed session validation
- Encrypted session data with XChaCha20-Poly1305
- Argon2id password hashing

**Rate Limiting**:
- Clerk endpoints use user-based rate limiting (more generous)
- Legacy endpoints use IP-based rate limiting
- Distributed across all application instances
- Automatic cleanup of expired entries

**Audit Logging**:
- All authentication events logged
- Security events include IP and user agent
- Failed attempts tracked for account protection
- Webhook events for external monitoring

**Implementation Files**:
- Clerk functions: `backend/auth/clerk_functions.go`
- Clerk middleware: `backend/auth/clerk_middleware.go`
- Session management: `backend/auth/clerk_session.go`
- Webhook handling: `backend/handlers/clerk_webhook.go`
- Rate limiting: `backend/middleware/rate_limit.go`
