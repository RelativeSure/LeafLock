## Common Admin Operations

### Reset User MFA via Clerk Dashboard

1. Go to [Clerk Dashboard](https://dashboard.clerk.com)
2. Find user by email or ID
3. Click user profile → **Security** → **Reset MFA**
4. Confirm operation
5. Notify user

### Reset User MFA via API

```bash
# Disable MFA for user
curl -X POST \
  "https://api.clerk.com/v1/users/{USER_ID}/mfa" \
  -H "Authorization: Bearer {CLERK_SECRET_KEY}" \
  -d '{"disabled": true}'

# Force password reset
curl -X POST \
  "https://api.clerk.com/v1/users/{USER_ID}/password" \
  -H "Authorization: Bearer {CLERK_SECRET_KEY}" \
  -d '{"password": "temp_password", "require_password_change": true}'
```

### Check User MFA Status

```bash
# Get user MFA information
curl -X GET \
  "https://api.clerk.com/v1/users/{USER_ID}/mfa" \
  -H "Authorization: Bearer {CLERK_SECRET_KEY}"
```

## Database Queries (Reporting Only)

### Authentication Method Distribution

```sql
-- Users by authentication type
SELECT
  CASE 
    WHEN clerk_user_id IS NOT NULL THEN 'Clerk'
    ELSE 'Legacy JWT'
  END as auth_method,
  COUNT(*) as user_count,
  ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 2) as percentage
FROM users
WHERE deleted_at IS NULL
GROUP BY auth_method
ORDER BY user_count DESC;
```

### Admin Users by Authentication Type

```sql
-- Security check: Admin authentication methods
SELECT
  CASE 
    WHEN clerk_user_id IS NOT NULL THEN 'Clerk'
    ELSE 'Legacy JWT'
  END as auth_method,
  COUNT(*) as admin_count
FROM users
WHERE is_admin = true
  AND deleted_at IS NULL
GROUP BY auth_method;
```

### Recent User Activity

```sql
-- Active users in last 30 days
SELECT
  u.id,
  u.email_encrypted,
  u.last_login,
  CASE 
    WHEN u.clerk_user_id IS NOT NULL THEN 'Clerk'
    ELSE 'Legacy JWT'
  END as auth_method,
  EXTRACT(DAY FROM NOW() - u.last_login) as days_since_login
FROM users u
WHERE u.last_login > NOW() - INTERVAL '30 days'
  AND u.deleted_at IS NULL
ORDER BY u.last_login DESC;
```

## Security Monitoring Queries

### Failed Login Attempts (Clerk Events)

```sql
-- Check for suspicious activity (Clerk users)
SELECT
  al.created_at,
  al.user_id,
  al.action,
  al.ip_address_encrypted,
  al.metadata_encrypted
FROM audit_log al
WHERE al.action IN ('login.failed', 'clerk.auth_failed')
  AND al.created_at > NOW() - INTERVAL '1 hour'
ORDER BY al.created_at DESC;
```

### Admin Activity Monitoring

```sql
-- Recent admin actions
SELECT
  al.created_at,
  al.user_id,
  al.action,
  al.metadata_encrypted
FROM audit_log al
WHERE al.action LIKE 'admin.%'
  OR al.action LIKE 'clerk.%'
  AND al.created_at > NOW() - INTERVAL '24 hours'
ORDER BY al.created_at DESC;
```

## Common Issues & Solutions

### Issue: "Invalid Clerk token"
**Cause**: Wrong secret key or token expired
**Solution**: Check `CLERK_SECRET_KEY` environment variable

### Issue: "User not found"
**Cause**: Clerk user ID doesn't exist
**Solution**: Verify user exists in Clerk dashboard

### Issue: "MFA not working"
**Cause**: Time sync or wrong method
**Solution**: Check device time, try backup method

### Issue: "Webhook verification failed"
**Cause**: Invalid signature
**Solution**: Verify webhook secret and signature calculation

### Issue: "Rate limited"
**Cause**: Too many requests
**Solution**: Wait for rate limit to reset, check Clerk dashboard

### Alert Conditions

```sql
-- High failed login rate (Clerk users)
SELECT COUNT(*)
FROM audit_log
WHERE action = 'clerk.auth_failed'
  AND created_at > NOW() - INTERVAL '5 minutes'
HAVING COUNT(*) >= 10;

-- Suspicious admin activity
SELECT COUNT(*)
FROM audit_log
WHERE action LIKE 'admin.clerk_%'
  AND created_at > NOW() - INTERVAL '1 hour'
HAVING COUNT(*) >= 5;
```

## Emergency Procedures

### Clerk API Down
1. Check https://status.clerk.com
2. Enable maintenance mode if available
3. Notify users of authentication issues
4. Monitor for resolution

### Security Incident
1. Check Clerk dashboard for unusual activity
2. Reset affected user MFA via dashboard
3. Force password resets for compromised accounts
4. Review audit logs
5. Document incident

### Mass MFA Reset Needed
1. Use Clerk dashboard bulk operations
2. Or use API script for automation
3. Notify all affected users
4. Provide new setup instructions
5. Monitor re-enablement rates
